Documentação Técnica — LOGIEXPRESS 1.1

Engenharia reversa da aplicação: entendendo o sistema a partir do código que já está funcionando.

Objetivo: compreender como cada parte do LOGIEXPRESS se conecta, antes de começar a desenvolver novas funcionalidades.

1. Visão geral da arquitetura

Navegador
    ↓
HTML + Jinja2 + Bootstrap + CSS
    ↓
Flask / Python
    ↓

O navegador solicita uma página. O Flask recebe a requisição por uma rota, consulta ou altera os dados por meio do SQLAlchemy e entrega um template HTML preenchido com os dados.

4. Modelo Cliente

class Cliente(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    nome = db.Column(db.String(120), nullable=False)
    documento = db.Column(db.String(20), unique=True, nullable=False)
    cidade = db.Column(db.String(80), nullable=False)
    uf = db.Column(db.String(2), nullable=False)
    ativo = db.Column(db.Boolean, default=True)
    pedidos = db.relationship("Pedido", backref="cliente", lazy=True)

Esse modelo representa uma tabela. Cada objeto Cliente representa um registro. A propriedade pedidos representa o relacionamento com os pedidos.

5. CRUD de Clientes

O cadastro foi implementado de forma específica para demonstrar o ciclo completo:

OperaçãoRotaO que acontece
CREATE/clientes/novoRecebe o formulário, valida e grava um cliente.
READ/clientesConsulta e lista clientes.
READ/clientes/<id>Mostra um cliente individualmente.
UPDATE/clientes/<id>/editarValida e altera os dados.
DELETE/clientes/<id>/excluirExclui somente quando a regra de negócio permite.

6. Regra de negócio da exclusão

O sistema não permite apagar um cliente que possua pedidos vinculados.

quantidade_pedidos = Pedido.query.filter_by(
    cliente_id=cliente.id
).count()

if quantidade_pedidos > 0:
    flash("Não é possível excluir este cliente...", "warning")

Por que isso é importante? Porque uma aplicação real precisa proteger a integridade dos dados. Um CRUD não deve apenas executar comandos; ele precisa respeitar as regras do negócio.

8. Jinja2

Jinja2 permite misturar HTML com dados enviados pelo Flask.

{% raw %}{% for cliente in clientes %}
    <tr>
        <td>{{ cliente.id }}</td>
        <td>{{ cliente.nome }}</td>
        <td>{{ cliente.cidade }} / {{ cliente.uf }}</td>
    </tr>
{% endfor %}{% endraw %}

9. O que o aluno deve observar

  • Uma rota representa uma entrada da aplicação.
  • GET normalmente consulta ou exibe uma página.
  • POST envia dados para processamento.
  • O modelo representa dados persistidos.
  • SQLAlchemy traduz operações Python em operações no banco.
  • O template transforma dados em HTML.
  • Git registra a evolução do código.
  • Uma branch permite desenvolver uma funcionalidade isoladamente.
  • Um Pull Request permite revisar a alteração antes da integração.
